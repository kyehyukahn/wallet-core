# 612. CI Release 자동화 — Design

**Date**: 2026-05-30
**Branch**: `feature/ci-release-automation` (dev에서 분기, PR 후 dev 머지)
**Scope**: 태그 push로 GitHub Actions가 빌드 → GitHub Release 생성 → @kyehyukahn/wallet-core npm publish까지 한 번에. 현재 [610](610.distribution-npm-github-packages.md)에 적힌 5단계 수동 절차를 1단계로 축약.

## 1. 트리거 & 권한

```yaml
on:
  push:
    tags: ['v*.*.*']
  workflow_dispatch:
    inputs:
      tag:
        description: 'Tag to release (e.g., v0.1.1, must already exist)'
        required: true

permissions:
  contents: write   # GitHub Release 생성
  packages: write   # GitHub Packages npm publish

concurrency:
  group: release-${{ github.ref }}
  cancel-in-progress: false
```

수동 dispatch는 기존 태그를 재실행할 때만 사용 (실패 후 재시도 등). 새 버전은 항상 태그 push로.

## 2. 단일 Job 구조 (`runs-on: macos-15-xlarge`)

| # | Step | 핵심 |
|---|---|---|
| 1 | Checkout | `actions/checkout@v4`, 해당 태그 SHA |
| 2 | Verify version sync | 태그(`v0.1.1`) ↔ `npm-package/package.json` version 일치 검사. 불일치 시 fail-fast |
| 3 | Install system deps | `tools/install-sys-dependencies-mac` |
| 4 | Cache Rust | `Swatinem/rust-cache@v2`, `workspaces: rust` |
| 5 | Install Rust deps | `tools/install-rust-dependencies` |
| 6 | Cache internal deps | `actions/cache@v4`, path `build/local`, key from `tools/install-dependencies` + `dependencies-version` 해시 |
| 7 | Install internal deps | `tools/install-dependencies` (cache miss 시) |
| 8 | Install Android cmake | `sdkmanager "cmake;3.18.1"` (607 트러블슈팅에 기록된 막힘 회피) |
| 9 | Generate iOS files | `tools/generate-files ios` → `swift/WalletCoreRs.xcframework` |
| 10 | Build iOS xcframework | `tools/ios-build` → `build/ios-frameworks/WalletCoreCommon.xcframework` |
| 11 | Generate Android files | `tools/generate-files android` |
| 12 | Build Android AAR | `tools/android-build` → `build/wallet-core.aar` |
| 13 | Pack release | `tools/release-pack ${VERSION}` → `build/release-v${VERSION}/` |
| 14 | Create GitHub Release | `softprops/action-gh-release@v2`, body_path `docs/release-notes/${TAG}.md`, files `build/release-v${VERSION}/*` |
| 15 | Setup Node + Packages auth | `actions/setup-node@v4` (registry-url + scope) |
| 16 | npm publish | `npm publish` (working-directory `npm-package`) with `NODE_AUTH_TOKEN: secrets.GITHUB_TOKEN` |
| 17 | Job summary | `$GITHUB_STEP_SUMMARY`에 Release/npm 패키지 URL + 산출물 크기 |

테스트 스텝 없음 — 태그가 가리키는 커밋은 이미 정규 CI(`ios-ci.yml`/`android-ci.yml`/`rust.yml`)에서 검증됐다는 전제. Release 워크플로의 책임은 산출물 생산.

## 3. 캐시 / 시간 예산

- 첫 실행 (캐시 미적중): 25~35분
- 캐시 적중: 12~18분
- 캐시 hit ratio는 Cargo.lock / install-dependencies-* 파일 변경 빈도에 좌우

## 4. 실패 처리 모델

- 1~13 실패 → 외부 영향 0 (Release 미생성, npm 미발행)
- 14 성공 + 16 실패 → Release 있고 npm 없음. 메인테이너가 `cd npm-package && npm publish` 수동 보완 ([610](610.distribution-npm-github-packages.md) §2 Step 5 그대로)
- 동일 태그 재실행:
  - 자산 갱신: gh-release action이 덮어씀 (의도된 동작)
  - npm publish: 이미 발행된 버전이면 npm이 fail (정상 — npm 정책상 동일 버전 재발행 금지)

## 5. 새 버전 cut 절차 (자동화 후)

기존 5단계가 1단계로 축약:

```bash
# 1. (사전) npm-package/package.json version bump + 커밋 + push
$EDITOR npm-package/package.json
git add npm-package/package.json
git commit -m "chore(npm): bump @kyehyukahn/wallet-core to 0.1.1"
git push

# 2. release notes 작성
$EDITOR docs/release-notes/v0.1.1.md
git add docs/release-notes/v0.1.1.md
git commit -m "docs(release-notes): v0.1.1"
git push

# 3. 태그 + push — CI가 나머지 다 처리
git tag -a v0.1.1 -m "v0.1.1"
git push origin v0.1.1
```

빌드는 macOS 러너에서 자동, 결과는 Actions 페이지 + 새 Release 페이지.

## 6. 함께 변경되는 문서

- `docs/610.distribution-npm-github-packages.md` §2를 "자동" + "수동 fallback" 구조로 재작성. §5 "향후 자동화 후보"는 "완료" 표시 또는 제거.
- 새 파일 추가 안 함 (612 자체가 설계 기록 + 워크플로우 자체가 1차 문서).

## 7. 스코프 제외

- 캐시 워밍 cron
- macOS 외 OS 빌드
- Sigstore / cosign 등 추가 서명 (SHA256SUMS로 충분)
- iOS device platform 컴포넌트 자동 설치 — 러너 기본 제공 가정, 첫 실행에서 실패 시 추가
