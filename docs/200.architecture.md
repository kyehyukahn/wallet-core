# 200. Wallet-Core 소프트웨어 아키텍처

> Trust Wallet Core는 130개 이상의 블록체인을 지원하는 크로스 플랫폼 암호화폐 지갑 라이브러리이다.
> C++ 코어 위에 C ABI를 노출하고, 그 위에 Swift/Kotlin/WASM/Rust 바인딩을 자동 생성하는 구조로 설계되었다.

## 3. 핵심 블록 다이어그램: 트랜잭션 서명 플로우

전체 시스템의 가장 중요한 데이터 흐름인 **트랜잭션 서명**을 추적한다.

```
  ┌─────────────────────┐
  │  모바일 앱 / dApp    │
  │                     │
  │  SigningInput proto  │  ← 사용자가 트랜잭션 파라미터 구성
  │  (체인별 Protobuf)   │    (to, amount, fee, private_key 등)
  └──────────┬──────────┘
             │ serialized bytes
             ▼
  ┌─────────────────────┐
  │   TWAnySignerSign   │  ← C API 진입점
  │  (include/TW*.h)    │
  └──────────┬──────────┘
             │
             ▼
  ┌─────────────────────────────────────────────┐
  │          Coin Dispatcher                     │
  │  src/Coin.cpp :: coinDispatcher(coinType)    │
  │                                              │
  │  switch(blockchain) {                        │
  │    Bitcoin    → bitcoinDP.sign()             │
  │    Ethereum   → ethereumDP.sign()   ────────────┐  C++ 레거시
  │    Cardano    → cardanoDP.sign()             │  │
  │    ...                                       │  │
  │    Solana     → rustEntry.sign()  ──────┐    │  │
  │    TON        → rustEntry.sign()  ──────┤    │  │
  │    ...                                  │    │  │
  │  }                                      │    │  │
  └─────────────────────────────────────────┘    │  │
                                  │              │  │
                  ┌───────────────┘              │  │
                  │  C++ → Rust FFI              │  │
                  ▼                              │  │
  ┌──────────────────────────────────┐          │  │
  │    tw_any_coin::AnySigner        │          │  │
  │                                  │          │  │
  │  fn sign(input, coin_type) {     │          │  │
  │    let (ctx, entry) =            │          │  │
  │      coin_dispatcher(coin_type); │          │  │
  │    entry.sign(&ctx, input)       │          │  │
  │  }                               │          │  │
  └──────────────┬───────────────────┘          │  │
                 │                              │  │
                 ▼                              │  │
  ┌──────────────────────────────────┐          │  │
  │  tw_coin_registry::dispatcher    │          │  │
  │                                  │          │  │
  │  match coin_type {               │          │  │
  │    Bitcoin  → BitcoinEntry       │          │  │
  │    Solana   → SolanaEntry        │          │  │
  │    Cosmos   → CosmosEntry        │          │  │
  │    ...                           │          │  │
  │  }                               │          │  │
  └──────────────┬───────────────────┘          │  │
                 │                              │  │
                 ▼                              ▼  ▼
  ┌─────────────────────────────────────────────────────────┐
  │              Chain-Specific CoinEntry.sign()             │
  │                                                         │
  │  1. Protobuf 역직렬화  (SigningInput → 구조체)           │
  │  2. 트랜잭션 구성       (체인별 포맷)                     │
  │  3. 서명 해시 계산      (tw_hash)                        │
  │  4. 개인키로 서명       (tw_keypair)                     │
  │  5. 서명된 트랜잭션 직렬화 (SigningOutput → bytes)        │
  └─────────────────────────────────────────────────────────┘
```

## 5. 핵심 추상화 (Trait 계층)

### 5.1 CoinEntry — 블록체인 플러그인 인터페이스

모든 블록체인이 구현해야 하는 핵심 트레이트:

```rust
// rust/tw_coin_entry/src/coin_entry.rs

pub trait CoinEntry {
    type AddressPrefix: Prefix;
    type Address: CoinAddress;
    type SigningInput<'a>: MessageRead<'a> + MessageWrite;
    type SigningOutput: MessageWrite;
    type PreSigningOutput: MessageWrite;

    // 선택적 모듈 (No* 변형으로 비활성화 가능)
    type JsonSigner: JsonSigner;
    type PlanBuilder: PlanBuilder;
    type MessageSigner: MessageSigner;
    type WalletConnector: WalletConnector;
    type TransactionDecoder: TransactionDecoder;
    type TransactionUtil: TransactionUtil;

    // 필수 구현
    fn parse_address(&self, coin: &dyn CoinContext, address: &str,
                     prefix: Option<Self::AddressPrefix>) -> AddressResult<Self::Address>;

    fn derive_address(&self, coin: &dyn CoinContext, public_key: PublicKey,
                      derivation: Derivation, prefix: Option<Self::AddressPrefix>)
                      -> AddressResult<Self::Address>;

    fn sign(&self, coin: &dyn CoinContext, input: Self::SigningInput<'_>)
            -> Self::SigningOutput;

    fn preimage_hashes(&self, coin: &dyn CoinContext, input: Self::SigningInput<'_>)
                       -> Self::PreSigningOutput;

    fn compile(&self, coin: &dyn CoinContext, input: Self::SigningInput<'_>,
               signatures: Vec<SignatureBytes>, public_keys: Vec<PublicKeyBytes>)
               -> Self::SigningOutput;
}
```

### 5.2 체인 구현 패턴

각 블록체인 크레이트는 동일한 구조를 따른다:

```
chains/tw_{blockchain}/src/
├── lib.rs              # pub mod 선언
├── entry.rs            # CoinEntry trait 구현  ← 핵심
├── context.rs          # 체인 컨텍스트 (CoinContext 구현)
└── modules/
    ├── signer.rs       # 트랜잭션 서명 로직

## 7. C++ ↔ Rust FFI 브릿지

마이그레이션된 체인은 C++ → Rust로 위임된다:

```
┌────────────────────────┐          ┌────────────────────────┐
│      C++ Layer         │          │      Rust Layer        │
│                        │          │                        │
│  RustCoinEntry.h       │   FFI   │  tw_any_coin/ffi/      │
│  ┌──────────────────┐  │ ◀─────▶ │  ┌──────────────────┐  │
│  │ sign() {         │  │  C ABI  │  │ tw_any_signer_   │  │
│  │   tw_any_signer_ │──┼────────▶│  │   sign()         │  │
│  │     sign(bytes,  │  │         │  │                  │  │
│  │       coin_type) │  │         │  │  → dispatcher    │  │
│  │ }                │  │         │  │  → chain.sign()  │  │
│  └──────────────────┘  │         │  └──────────────────┘  │
│                        │         │                        │
│  데이터 전달:           │         │  결과 반환:            │
│  Protobuf bytes        │────────▶│  Protobuf bytes       │
│  (포인터 + 길이)       │◀────────│  (포인터 + 길이)      │
└────────────────────────┘         └────────────────────────┘

메모리 안전:
- tw_memory::RawPtr로 포인터 래핑
- zeroize로 개인키 메모리 자동 소거
- unsafe는 FFI 경계에만 캡슐화
```

  4. tools/generate-files로 Swift/Kotlin/WASM 바인딩 재생성
```

## 15. SPV/Wallet 확장 레이어 (Phase 1-4)

기존 wallet-core의 서명 전용 아키텍처 위에, 선택적 SPV 동기화와 월렛 상태 관리 레이어를 추가했다.

### 15-1. 레이어 구조

```
기존 (유지):
  TWAnySigner → CoinEntry::sign() → 트랜잭션 서명 (stateless)

신규 (선택적):
  TWHDWallet (C++) → xpub 생성
       ↓
  BitcoinWalletManager (Rust)
       ├── Wallet → AddressManager (BIP32 주소 파생, gap limit)
       │          → UtxoTracker   (UTXO 집계, 잔액 계산)
       │          → TxTracker     (트랜잭션 히스토리, reorg 처리)
       │
       ├── SyncManager → PeerManager → Peer (P2P 핸드셰이크)
       │               → BloomFilter (BIP37)
       │               → MerkleBlock (머클 증명 검증)
       │
       └── Persistence (앱이 구현체 제공)
```

### 15-2. 신규 Rust crate

| Crate | 위치 | 역할 |
|-------|------|------|
| `tw_spv` | `rust/frameworks/tw_spv/` | P2P 네트워킹, 헤더 동기화, BIP37 필터링, 머클 검증 |
| `tw_wallet_manager` | `rust/frameworks/tw_wallet_manager/` | 월렛 상태 관리, 주소 파생, UTXO/TX 추적, 영속화/복구 |

## 16. 요약: 아키텍처 핵심 원칙

1. **C ABI가 계약이다** — 모든 언어 바인딩(Swift, Kotlin, WASM, Flutter, Rust)은 C 헤더에서 자동 생성된다. 수동 편집 금지.
2. **Protobuf이 데이터 포맷이다** — 모든 서명 입출력은 Protobuf으로 직렬화되어 언어 경계를 넘는다.
3. **registry.json이 단일 진실이다** — 코인 메타데이터(SLIP44, 주소 형식, 커브 타입)의 유일한 원본.
4. **플러그인 아키텍처** — `CoinEntry` 트레이트를 구현하면 새 블록체인이 자동으로 통합된다.
5. **점진적 Rust 마이그레이션** — 레거시 C++ 체인과 현대 Rust 체인이 동일한 C ABI 뒤에서 공존한다.
6. **프레임워크 재사용** — UTXO/EVM/Cosmos/Substrate 프레임워크로 유사 체인의 코드 중복을 최소화한다.
7. **SPV는 선택적 레이어** — 기존 서명 API를 변경하지 않으며, SPV/Wallet 기능은 독립 crate로 추가. 앱이 필요한 경우에만 사용.
8. **빌드 산출물은 플랫폼별 분리** — Rust .rlib → C 정적 라이브러리 → 플랫폼 패키지 (.aar / .framework / .wasm) 순서로 생성.
