# v0.3.0 — postinstall checksum pinning (audit W-01)

Minor release. **Security fix.** Closes audit W-01: the v0.2.x postinstall
downloaded its expected SHA-256 checksums from the same release host as
the binaries themselves, so a compromised release source or
`WALLET_CORE_RELEASE_BASE_URL` env override could swap binaries and
checksums together and the integrity check would pass against the
attacker's own ground truth.

Single-focus release. No source code change, no native binary change,
no TS/Kotlin/Swift API change.

## Why this release (W-01)

`cirqle-mobile/docs/native/125.audit-wallet-key-leak.md §W-01` flagged
the self-referential checksum download as a Tier-0 finding: the entire
key custody surface routes through `wallet.core.jni.*` which is loaded
from `wallet-core.aar` (split into `wallet-core-classes.jar` +
`jniLibs/<ABI>/libTrustWalletCore.so` since v0.2.17). If those binaries
can be replaced at install time, every signing call, mnemonic
generation, and seed derivation runs through attacker-controlled code.
The cirqle audit already locked the consumer side
(`frozen-lockfile=true`, exact pin `0.2.18`, `@kyehyukahn` scope pinned
in `.npmrc`); v0.3.0 closes the upstream half.

## The shape of the fix

### 1. Embedded SHA-256 pin (single source of truth)

`tools/release-pack` now copies `build/release-v<version>/SHA256SUMS`
into `npm-package/native-pins/SHA256SUMS` at pack time. `package.json`
`files:` allowlist includes `native-pins` so the file ships in every
npm tarball. The pin is part of what `npm publish` signs and what
`npm install` retrieves under whatever lockfile/integrity constraints
the consumer set.

### 2. `postinstall.js` verifies against the embedded pin only

The v0.2.x flow downloaded `${BASE_URL}/SHA256SUMS` and verified each
asset against the freshly-downloaded checksum file. That entire pattern
is gone in v0.3.0:

```js
// v0.3.0 npm-package/postinstall.js (excerpt)
const EMBEDDED_PIN = path.join(PKG_DIR, 'native-pins', 'SHA256SUMS');

if (!fs.existsSync(EMBEDDED_PIN)) {
  die(`postinstall pin missing — refusing to fall back to remote SHA256SUMS (W-01).`);
}
const sums = parseSums(fs.readFileSync(EMBEDDED_PIN, 'utf8'));

for (const a of ASSETS) {
  const expected = sums[a.name];
  if (!expected) die(`embedded pin missing entry for ${a.name}`);
  await downloadToFile(`${BASE_URL}/${a.name}`, local);
  const actual = sha256OfFile(local);
  if (actual !== expected) die(`checksum mismatch for ${a.name}`);
}
```

The `downloadString(url)` helper (the only function that fetched the
remote SUMS) is removed entirely — no code path can fall back to it.

### 3. `WALLET_CORE_RELEASE_BASE_URL` override semantics

`WALLET_CORE_RELEASE_BASE_URL` remains available (legitimate mirroring,
air-gapped CI). Override no longer changes what the integrity check
trusts — the embedded pin is still authoritative. If the mirror serves
bytes that don't match what the original release produced, postinstall
aborts. Override is loud: a warning is emitted to stderr at install
time so the consumer knows their assets came from a non-default host.

**No escape-hatch env exists by design.** The audit explicitly calls
out that any opt-out env becomes its own attack surface (one flipped
env var in a deploy config = full bypass). If a future legitimate use
case needs to install with a pin mismatch, fix it by re-publishing
correct binaries or by overriding `WALLET_CORE_SKIP_DOWNLOAD=1` and
laying out the native tree manually — both are visible / loud paths.

## release-pack invariant guards added

Guard #14 — three checks at pack time:

1. `npm-package/native-pins/SHA256SUMS` is present after pack and has
   at least 5 entries (xcframework × 2, AAR, proto.jar, swift-sources).
2. `npm-package/postinstall.js` references `native-pins/SHA256SUMS` and
   does NOT call `downloadString(BASE_URL + SUMS_FILE)`.
3. `npm-package/package.json` `files:` allowlist includes `native-pins`.

Any guard failure exits before tarball would be packaged.

## Consumer impact

**Zero beyond a version bump.**

```bash
cd ~/Develops/P_CirQle/cirqle-mobile/apps/mobile
# edit package.json: "@kyehyukahn/wallet-core": "0.3.0"   (exact pin, no caret)
rm -rf node_modules
pnpm install
# postinstall now logs: "loaded embedded SHA-256 pin (5 entries)"
# Each asset still downloaded over HTTPS, still SHA-256 verified — just
# against the embedded pin shipped in the tarball, not the remote SUMS.
pnpm android        # unchanged behavior
pnpm ios            # unchanged behavior
```

The download time, asset layout, and runtime path are byte-identical to
v0.2.18. Stage D byte-equal signing vectors carry through unchanged.

## Why minor bump (0.2.x → 0.3.0)

- `postinstall.js` behavior change at install time. The check that
  passed against a remote SUMS in v0.2.x can fail against an embedded
  pin in v0.3.0 if a mirror serves stale/wrong bytes — same code path,
  semantically different gate.
- A new file ships in the tarball (`native-pins/SHA256SUMS`).
- The `downloadString` helper is removed from the published JS.

No API surface change. No runtime code change. Stage D byte-equal
vectors are byte-identical because the .so / classes.jar contents
don't change.

## Native binaries

**Content-identical to v0.2.18.** Re-packed by `tools/release-pack`
from the same unchanged build outputs (`build/wallet-core.aar`,
`build/ios-frameworks/WalletCoreCommon.xcframework`,
`swift/WalletCoreRs.xcframework`,
`android/wallet-core-proto/build/libs/wallet-core-proto.jar`,
`swift/Sources/`). Per-asset:

| Asset | byte-identical vs v0.2.18? | Why |
|---|---|---|
| `wallet-core.aar` | yes | plain file copy |
| `wallet-core-proto.jar` | yes | plain file copy |
| `WalletCoreCommon.xcframework.zip` | no | `ditto -c -k` re-pack metadata |
| `WalletCoreRs.xcframework.zip` | no | `ditto -c -k` re-pack metadata |
| `swift-sources.tar.gz` | no | `tar -czf` re-pack metadata |

`SHA256SUMS` is regenerated and ships embedded.

## What was not touched

- TypeScript surface (`src/`, `evm/`, `solana/`) — no change.
- Native bridge (`wallet.core.jni.*`, Swift wrappers, Kotlin
  `WalletCoreModule.kt` including v0.2.15 `System.loadLibrary` companion
  init) — no change.
- `npm-package/android/build.gradle` (postinstall AAR-unpack pattern
  from v0.2.17/v0.2.18) — no change.
- iOS pack-time invariants (guards #1–#10) — no change.
- AGP 8.x pattern guards (#11–#13) — no change.
- Peer deps — no change.
