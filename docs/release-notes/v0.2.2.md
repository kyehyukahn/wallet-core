# v0.2.2 — swift-sources includes generated `*.pb.swift`

Patch release. iOS-only fix. The TypeScript surface, native bridge
methods, error messages, proto shapes, and supported coin set are all
**identical to v0.2.1**.

## Why this release

Reported by the cirqle-mobile native dev after v0.2.1's `pod install`
fix landed and Stage B reached `xcodebuild`. The build failed with:

```
Pods/WalletCoreModule/chains/EvmSigning.swift:12:14: error:
  cannot find type 'TW_Ethereum_Proto_TransactionMode' in scope

Pods/WalletCoreModule/chains/EvmSigning.swift:109:71: error:
  cannot find type 'TW_Ethereum_Proto_Transaction' in scope
```

### Root cause

`tools/generate-files ios` runs two protoc passes against `src/proto/*.proto`:

1. `protoc --swift_out=swift/Sources/Generated/Protobuf` (line 71) — emits the
   actual struct/enum definitions: `Ethereum.pb.swift` containing
   `public struct TW_Ethereum_Proto_Transaction`, `public enum
   TW_Ethereum_Proto_TransactionMode`, etc.
2. `protoc --plugin=protoc-gen-swift-typealias` (line 87) — emits the
   `+Proto.swift` typealias bridges (`Ethereum+Proto.swift`:
   `typealias EthereumTransaction = TW_Ethereum_Proto_Transaction`).

Pass 1 is **conditional** on `protoc-gen-swift` being discoverable via
`command -v`. The v0.2.0 / v0.2.1 local build host ran the script
without `protoc-gen-swift` on PATH, so pass 1 was silently skipped:
the swift sources tree shipped 60 typealias bridges with **zero** of
the underlying struct definitions. Every `TW_*_Proto_*` symbol was a
dangling reference; consumer code touching the protobuf types (this
package's own `chains/EvmSigning.swift`, plus anything consumers add
later) failed to compile.

`protoc-gen-swift` is in fact bundled at `build/local/bin/`, but only
visible if `tools/generate-files` is invoked with `PWD` at the repo
root (so the script's `PREFIX=$PWD/build/local` block triggers and it
prepends `build/local/bin` to PATH). The original build did not do
this. Lesson: trust the invariant guard, not the operator.

## What changed

| File / Asset | Change |
|---|---|
| `swift/Sources/Generated/Protobuf/*.pb.swift` (60 files) | regenerated with `protoc --swift_out`; contains the actual `public struct TW_<Chain>_Proto_*` definitions referenced by the typealiases and by `chains/EvmSigning.swift`, `chains/SolanaSigning.swift`, etc. |
| `npm-package/package.json` | `version` 0.2.1 → 0.2.2 |
| `tools/release-pack` | **invariant guard added.** After tarring `swift-sources.tar.gz`, the script now greps the tarball table-of-contents for `\.pb\.swift$` and bails with `exit 3` if zero entries are found, or if `Ethereum.pb.swift` / `Solana.pb.swift` / `Common.pb.swift` are missing. This class of regression cannot ship again silently. |
| `npm-package/ios/WalletCoreModule.podspec` | unchanged (v0.2.1 relative-paths fix still correct) |
| `npm-package/package.json` peerDependencies | unchanged (v0.2.1 `expo-modules-core: "*"` still correct) |
| Native xcframeworks / AAR / proto JAR | unchanged from v0.2.0 (binaries unaffected — pure C/Rust ABI) |

## Consumer migration: v0.2.1 → v0.2.2

```bash
pnpm add @kyehyukahn/wallet-core@^0.2.2
pnpm exec expo prebuild --clean
pnpm ios   # or pnpm android
```

No code change required. No native bridge change. No TS API change.
Drop-in.

## Verification

- `find swift/Sources -name "*.pb.swift" | wc -l` = 60 (vs 0 before).
- `grep -l 'public struct TW_Ethereum_Proto_Transaction' swift/Sources/Generated/Protobuf/Ethereum.pb.swift` resolves.
- `tar -tzf build/release-v0.2.2/swift-sources.tar.gz | grep -c '\.pb\.swift$'` reports 60.
- Local `npm install @kyehyukahn/wallet-core@0.2.2` runs postinstall → 5/5 assets verified → `node_modules/@kyehyukahn/wallet-core/native/ios/Sources/Generated/Protobuf/Ethereum.pb.swift` is present.
