# v0.2.8 — Swift imports for extension files + strip codegen/header mismatch

iOS-only patch over v0.2.7. xcframework / AAR / proto.jar binaries are byte-identical to v0.2.7; only the `swift-sources.tar.gz` content changes.

## What was broken

After v0.2.7 fixed the deriveAddress API, xcodebuild left two distinct error categories:

### 1. Pure-extension Swift files without `import Foundation`

```
.../Sources/Generated/HDVersion+Extension.swift:14:16: error: cannot find 'TWHDVersionIsPublic' in scope
.../Sources/Generated/HDVersion+Extension.swift:21:16: error: cannot find 'TWHDVersionIsPrivate' in scope
```

The v0.2.5 sed pass added `import WalletCoreCommon` after `import Foundation`. Pure `extension TWxxx { … }` files (HDVersion+Extension and similar) skip Foundation entirely, so the sed couldn't find an anchor and the file got no import.

### 2. Swift wrapper calling a TW function the shipped C header doesn't declare

```
.../Sources/Generated/CryptoBoxSecretKey.swift:34:45: error: cannot find 'TWCryptoBoxSecretKeyGetPublicKey' in scope
```

Verified the C header:

```bash
$ grep -E "TW_EXPORT" .../WalletCoreCommon.framework/Headers/TWCryptoBoxSecretKey.h
TW_EXPORT_CLASS
TW_EXPORT_PROPERTY TWData *_Nonnull TWCryptoBoxSecretKeyData(...)
# Only TWCryptoBoxSecretKeyData is exported. No TWCryptoBoxSecretKeyGetPublicKey.
```

The Swift wrapper was emitted from a codegen run that knew of a `TWCryptoBoxSecretKeyGetPublicKey` function which is NOT declared in the shipped C ABI. Cross-language drift: the C side is missing the export, but the Swift codegen still references it.

CryptoBox SecretKey isn't used by us (EVM + Solana signing don't touch it), so shipping a stubbed file is acceptable — but it must not BE in the tarball or the consumer pod will fail SwiftCompile.

## Fix

`tools/release-pack` gets two updates:

### Generalised `import WalletCoreCommon` insertion

Old (v0.2.5~v0.2.7): only insert after `import Foundation`.

New (v0.2.8): use awk to insert after `import Foundation` if present, otherwise insert before the first non-comment / non-blank line. Files are processed when they reference any TW symbol (`grep -qE 'TW[A-Z][A-Za-z]'`).

This now catches:
- `Sources/Generated/HDVersion+Extension.swift` — pure `extension` file
- `Sources/Generated/<Coin>+Extension.swift` — same shape
- any future codegen-emitted pure-extension files

### Strip files that reference C symbols not in the shipped headers

`tools/release-pack` gains a `SWIFT_SKIP` array and an `--exclude` arg for each entry to the `tar` invocation:

```bash
SWIFT_SKIP=(
    "Sources/Generated/CryptoBoxSecretKey.swift"
)
```

Adding a new mismatch is a one-line edit + new release + release-notes documentation of the symbol delta.

### Updated invariant guard

```
$ release-pack 0.2.8
Verifying every TW-using Swift file imports WalletCoreCommon...
  OK (all TW-using .swift files import WalletCoreCommon)
```

The check is now: "for every .swift file outside Sources/Generated/Protobuf/ that references a TW symbol, `import WalletCoreCommon` must appear". The wider net catches more potential regressions at pack time.
