# v0.3.1 — wrapper key-byte zeroization (audit W-06 upstream port)

Patch release. **Security hygiene fix, wrapper-only.** No native binary
change, no TS surface change, no API change.

## Why this release

cirqle-mobile audit 125 §W-06 flagged that signing helpers extract the
private key (`privateKey.data()` / `privateKey.data`) into a JVM
`ByteArray` / Swift `Data` and leave the plaintext bytes resident on the
heap after `AnySigner.sign` returns — recoverable by heap dump /
debugger / rooted-device forensics until GC / deinit. cirqle's local
`modules/secure-signer/` got the fix in cirqle-mobile PR #37; this
release ports the identical pattern to **this package's own Expo Module
wrappers**, which have the same shape (the audit handoff explicitly
noted "wallet-core 모듈 내부도 동형").

## What changed (4 files, same pattern)

| File | Chain |
|---|---|
| `npm-package/android/.../chains/EvmSigning.kt` | EVM |
| `npm-package/android/.../chains/SolanaSigning.kt` | Solana |
| `npm-package/ios/chains/EvmSigning.swift` | EVM |
| `npm-package/ios/chains/SolanaSigning.swift` | Solana |

Kotlin:

```kotlin
val pkBytes = privateKey.data()
try {
    // ... build SigningInput with ByteString.copyFrom(pkBytes) ... sign ...
} finally {
    Arrays.fill(pkBytes, 0.toByte())   // every exit path
}
```

Swift:

```swift
var pkData = privateKey.data           // Data is value-typed — our copy
var input = TW_..._Proto_SigningInput()
defer {
  pkData.resetBytes(in: 0..<pkData.count)
  input.privateKey = Data()
}
// ... build input with pkData ... sign ...
```

Both shapes guarantee the wipe on success, throw, and rethrow paths.
`ByteString.copyFrom()` (Kotlin) and Data's value semantics (Swift)
mean the wipe never corrupts the in-flight SigningInput.

## Scope and residual

Scope-narrowing, not zero-residual: wallet-core's native `PrivateKey`
handle keeps its own internal buffer whose lifetime is bound to the
JNI finalizer / Swift deinit — outside wrapper reach. The audit accepts
this residual (same note as cirqle PR #37). The mnemonic `String`
crossing the JS bridge is W-14 (audit-accepted residual; future
CharArray/[UInt8] channel per cirqle 124 §9.1).

## Consumer impact

Zero beyond a version bump. Wrapper sources compile in the consumer's
own build (they ship as source in the tarball); signing outputs are
byte-identical — Stage D vectors unaffected.

## Native binaries

Content-identical to v0.3.0 (re-packed from the same build outputs;
`wallet-core.aar` + `wallet-core-proto.jar` byte-identical, archive-
shaped assets re-packed). `native-pins/SHA256SUMS` regenerated and
embedded per v0.3.0's W-01 pinning.
