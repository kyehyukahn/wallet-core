# v0.2.1 — podspec relative paths + peerDeps fix

Patch release. No native artifacts changed; v0.2.1 ships the same
`WalletCoreCommon.xcframework`, `WalletCoreRs.xcframework`,
`wallet-core.aar`, `wallet-core-proto.jar`, and `swift-sources.tar.gz`
as v0.2.0 (byte-identical, re-uploaded for the v0.2.1 GitHub Release
so `postinstall.js`'s version-keyed download URL resolves).

## Why this release

Reported by the cirqle-mobile native dev during the v0.2.0 prebuild
gate. Two issues blocked / annoyed consumers; both are config-only.

### Issue 1 — `pod install` rejects absolute paths (BLOCKER)

`npm-package/ios/WalletCoreModule.podspec` used
`File.expand_path('..', __dir__)` to build paths for
`vendored_frameworks` and `source_files`. The result is an absolute
path, and CocoaPods file-pattern validation requires them to be
relative to the podspec dir:

```
ERROR | [iOS] File Patterns: File patterns must be relative and cannot start with a slash (source_files).
ERROR | File Patterns: File patterns must be relative and cannot start with a slash (vendored_frameworks).
```

**Fix:** drop the `File.expand_path` plumbing entirely; use
`../native/ios/...` globs anchored at the podspec dir. CocoaPods
resolves them natively against the spec's directory.

### Issue 2 — `peerDependencies.expo-modules-core` mismatch (WARNING)

Published v0.2.0 `package.json` declared
`"expo-modules-core": "^56.0.14"`. That major doesn't exist
(expo-modules-core is on 3.x in Expo SDK 54). The intent was the
"any version" wildcard documented in the CONTRACT.

**Fix:** `"expo-modules-core": "*"` — matches the CONTRACT and the
Expo Module DSL surface (stable since expo-modules-core 1.x).

## What changed

| File | Change |
|---|---|
| `npm-package/ios/WalletCoreModule.podspec` | absolute → relative `../native/ios/...` paths for `vendored_frameworks` and `source_files`; removed `File.expand_path`/`__dir__` plumbing. |
| `npm-package/package.json` | `version` 0.2.0 → 0.2.1. `peerDependencies.expo-modules-core` `^56.0.14` → `*`. |

No TypeScript surface change. No native code change. No Android
podspec-equivalent change (Android side uses Gradle and was unaffected).

## Consumer migration: v0.2.0 → v0.2.1

Drop-in. Bump the dep and re-prebuild:

```bash
pnpm add @kyehyukahn/wallet-core@^0.2.1
pnpm exec expo prebuild --clean
```

Then `pnpm ios` / `pnpm android` should complete pod install without
the "File patterns must be relative" error.

## Verification
