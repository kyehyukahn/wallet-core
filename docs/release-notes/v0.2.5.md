# v0.2.5 — module bridging for CocoaPods (xcframework module map + Swift imports)

iOS-only patch over v0.2.4. The shipped `swift-sources.tar.gz` now contains `import WalletCoreCommon` in every non-Protobuf source, and `WalletCoreCommon.xcframework` now ships a proper `Modules/module.modulemap` + `Headers/WalletCore.h` umbrella header per slice. AAR / proto.jar bytes unchanged.

## What was broken (B6, surfaced on v0.2.4)

v0.2.4 fixed B5 (SwiftProtobuf module alias). With B2 / B3 / B4 / B5 cleared, xcodebuild finally got to compile the `Generated/` Swift wrappers (`HDWallet.swift`, `AnySigner.swift`, `CryptoBoxSecretKey.swift`, etc.) and immediately failed on every TW* reference:

```
.../Sources/Generated/CryptoBoxSecretKey.swift:18:29: error: cannot find 'TWCryptoBoxSecretKeyData' in scope
.../Sources/Generated/DataVector.swift:18:16: error: cannot find 'TWDataVectorSize' in scope
.../Sources/Generated/DerivationPath.swift:18:34: error: cannot find 'TWDerivationPathPurpose' in scope
(repeats for ~200+ TW* identifiers across Generated/)
** BUILD FAILED **
```

Two cooperating root causes:

1. **`WalletCoreCommon.xcframework` ships no module map.** `tools/ios-build` produces the framework with `Headers/TW*.h` directly under `<slice>/WalletCoreCommon.framework/Headers/`, but no `Modules/module.modulemap` and no umbrella header. SwiftPM consumers don't need one (Package.swift's target dependency makes the C symbols visible); CocoaPods consumers do.

2. **Generated Swift wrappers don't `import WalletCoreCommon`.** `tools/generate-files ios` emits files like:
   ```swift
   import Foundation
   public final class CryptoBoxSecretKey { ... TWCryptoBoxSecretKeyData(rawValue) ... }
   ```
   No `import WalletCoreCommon` (or equivalent). The TW symbols are simply assumed to be in scope via the SwiftPM target boundary.

Once SwiftCompile started actually reading the Generated/ files (v0.2.4 was the first version where it did — B5 unblocked the protobuf compile, which in turn allowed the Generated/ batch to be reached), every TW reference failed.

## Fix

`tools/release-pack` now does two cooperating injections before producing the release artifacts:

### 1. xcframework: inject module.modulemap + umbrella header per slice

For each `<slice>/WalletCoreCommon.framework/` in the staged xcframework copy:

```
<slice>/WalletCoreCommon.framework/
├── Headers/
│   ├── WalletCore.h         ← injected (copied from swift/Sources/Generated/WalletCore.h)
│   └── TW*.h                (already present)
└── Modules/
    └── module.modulemap     ← injected
```

`module.modulemap` content:

```
framework module WalletCoreCommon {
  umbrella header "WalletCore.h"
  export *
  module * { export * }
}
```

The umbrella header `WalletCore.h` is generated by codegen and `#include`s every `TW*.h` transitively, so the module exports the full C ABI.

The staged xcframework is then zipped via `ditto`. Source xcframework on disk is not mutated.

### 2. Swift sources: `import WalletCoreCommon` after `import Foundation`

A sed pass inserts `import WalletCoreCommon` immediately after `import Foundation` in every non-Protobuf `.swift` file under `swift/Sources/`. Protobuf files (`Sources/Generated/Protobuf/*.swift`) are skipped — they only reference `SwiftProtobuf.*` symbols and don't need the framework module.

Idempotent: files that already import `WalletCoreCommon` are skipped.

### 3. Hard invariants at pack time

```
$ release-pack 0.2.5
...
Verifying WalletCoreCommon.xcframework has Modules/module.modulemap...
  OK (4 slice(s) with module.modulemap, 4 umbrella header(s))
Verifying non-Protobuf Swift files import WalletCoreCommon...
  OK (all non-Protobuf .swift files import WalletCoreCommon)
```

Pack-time guard count after v0.2.5:

| Guard | Closes | Since |
|---|---|---|
| `.pb.swift count ≥ 1` | B3 (missing protobuf) | v0.2.2 |
| `Ethereum/Solana/Common.pb.swift present` | B3 specifics | v0.2.2 |
| `0 WalletCoreSwiftProtobuf references` | B5 (alias module) | v0.2.4 |
| non-Protobuf `.swift` files `import WalletCoreCommon` | B6 (C scope) | v0.2.5 |
| xcframework has `Modules/module.modulemap` + umbrella | B6 (C scope) | v0.2.5 |

## What changed in release artifacts

| Asset | v0.2.4 | v0.2.5 |
|---|---|---|
| `WalletCoreCommon.xcframework.zip` | no Modules/module.modulemap | **Modules/module.modulemap + Headers/WalletCore.h per slice** |
| `WalletCoreRs.xcframework.zip` | unchanged | unchanged |
| `wallet-core.aar` | unchanged | unchanged |
| `wallet-core-proto.jar` | unchanged | unchanged |
| `swift-sources.tar.gz` | non-Protobuf files: `import Foundation` only | **non-Protobuf files: `import Foundation` + `import WalletCoreCommon`** |

iOS-only patch — Android consumers can stay on v0.2.3+. iOS consumers should bump to v0.2.5.

## Consumer migration

```bash
pnpm add @kyehyukahn/wallet-core@^0.2.5
pnpm install
pnpm exec expo prebuild --clean
# xcodebuild now expected to pass through Generated/ Swift wrappers
```

No podspec / build.gradle changes needed on the consumer side.
