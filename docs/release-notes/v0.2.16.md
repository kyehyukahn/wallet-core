# v0.2.16 — publish hygiene: stop bundling postinstall artifacts

Patch release. **Publish-pipeline-only fix.** No source code change of
any kind. The TypeScript surface, native bridge, error messages, proto
shapes, supported coin set, and the v0.2.15 Android JNI loadLibrary
fix are all carried forward unchanged.

## Why this release

While publishing v0.2.15, `npm publish`'s pre-flight summary reported:

```
npm notice package size: 116.4 MB
npm notice unpacked size: 377.6 MB
npm notice total files: 404
```

vs the expected ~18 KB / ~55 KB / ~30 files for a pure-source publish.
Tracing it back: this has been the state of every release since v0.2.6
(when xcframeworks were relocated from `<pkg>/native/ios/` into
`<pkg>/ios/` to dodge B7's `vendored_frameworks` `..` glob limitation).

### What was getting bundled

`package.json` had `files: ["dist", "ios", "android", ...]`. The
`ios` entry is a directory glob, so npm bundled **everything** under
it — including postinstall-extracted artifacts that exist only after
a local `npm install`:

| Path | Size | Source |
|---|---|---|
| `ios/WalletCoreCommon.xcframework/.../WalletCoreCommon` (binary) | 80.5 MB | postinstall extracted |
| `ios/WalletCoreRs.xcframework/{ios-arm64, ios-…-simulator, …-maccatalyst, macos-…}/libwallet_core_rs.a` × 4 | 101 MB total | postinstall extracted |
| `ios/__MACOSX/` | small | `unzip` metadata leftover on macOS |
| `ios/Sources/` (when last-extracted) | ~300 KB | postinstall extracted (v0.2.3+ layout) |

Net: ~100 MB of native binaries that the package's own
`postinstall.js` then downloads AGAIN from the GitHub Release. Double
bandwidth on every consumer install.

The `.gitignore` excluded `native/` and `ios/Sources/` but missed
`ios/*.xcframework/`. Even with those entries in `.gitignore`, npm's
`files:` allowlist is the dominant signal — anything matched by it
gets included regardless.

### Functional impact

For consumers: only bandwidth and disk waste. The package still
worked end-to-end (the bundled and re-downloaded artifacts are
byte-identical, postinstall's SHA verification still passes). cirqle
PR 3 Stage B / Stage D successes on v0.2.9 and v0.2.14 are unaffected
— iOS BUILD SUCCEEDED, Android BUILD SUCCESSFUL.

## Fix

### `package.json` — tighter `files:` allowlist

`files:` now enumerates **only** the source paths that exist before
postinstall runs:

```jsonc
"files": [
  "dist",
  "ios/WalletCoreModule.podspec",
  "ios/WalletCoreModule.swift",
  "ios/chains",
  "android/build.gradle",
  "android/src",
  "expo-module.config.json",
  "postinstall.js",
  "README.md"
]
```

No directory globs at the `ios/` or `android/` level — postinstall
artifacts cannot leak in even by accident.

### `npm-package/.gitignore` — belt + braces

Adds:

- `ios/*.xcframework/` — glob, covers future xcframework names too
- `ios/__MACOSX/` — `unzip` metadata cruft on macOS
- `android/build/` — gradle build output (a sibling of the already
  ignored `android/.gradle/`)

`.gitignore` doesn't override `files:`, but if a future contributor
broadens `files:` back to `["ios", ...]`, `.gitignore` becomes the
backstop.

### Version

`0.2.15` → `0.2.16`. No code change in `dist/`, `postinstall.js`, or
any Kotlin/Swift source.

## Consumer migration: v0.2.15 → v0.2.16

```bash
pnpm add @kyehyukahn/wallet-core@^0.2.16
pnpm exec expo prebuild --clean
```

Drop-in. The v0.2.15 Android JNI fix is preserved. Consumers will see
a much smaller tarball download on install. No platform rebuild
needed.

  to v0.2.15's static grep guard).
- Move iOS post-processing (sed normalisations, modulemap injection,
  strip-list) into `tools/ios-build` so artifacts are correct at
  source time rather than patched in release-pack.
