# v0.2.13 — let expo-module-gradle-plugin own all the publishing wiring

Android-only patch over v0.2.12. iOS artifacts byte-identical.

## What was broken

v0.2.12 added `publishing.singleVariant("release") { withSourcesJar() }` inside the `android { … }` block and `afterEvaluate { publishing { publications { release(MavenPublication) … } } }` at the bottom, on the theory that the missing-SoftwareComponent error in v0.2.10/v0.2.11 was caused by no one declaring them. After v0.2.12 fixed the unrelated `versionName package_json['version']` NameError, the build advanced one step and revealed the actual root cause:

```
A problem occurred configuring project ':kyehyukahn-wallet-core'.
> Failed to notify project evaluation listener.
   > Using singleVariant publishing DSL multiple times to publish variant "release"
     to component "release" is not allowed.
```

`expo-module-gradle-plugin` already calls `singleVariant("release")` on the library extension on our behalf. Our v0.2.11/v0.2.12 addition was a duplicate, which is hard-rejected at evaluation time. The "SoftwareComponent with name 'release' not found" error we saw on v0.2.10/v0.2.11 was actually the configure-time NameError on the undefined `package_json` variable, with the message lost in cascade reporting.

## Fix

Strip every publishing-related line we added. Let `expo-module-gradle-plugin` own that wiring entirely.

```diff
- apply plugin: 'maven-publish'
  apply plugin: 'expo-module-gradle-plugin'

  android {
      ...
-     publishing {
-         singleVariant("release") {
-             withSourcesJar()
-         }
-     }
  }

- afterEvaluate {
-     publishing {
-         publications {
-             release(MavenPublication) {
-                 from components.release
-                 groupId = group
-                 artifactId = 'wallet-core'
-                 version = package_version
-             }
-         }
-     }
- }
```

Kept the versionCode / versionName fix (v0.2.10), the package_version Groovy literal (v0.2.10), and the `package_version` reference in versionName (v0.2.12). Added a short comment in the android block noting that the publishing DSL belongs to the plugin and warning future maintainers not to re-add it.

## Lesson for the strip-list / future patches

When a tooling-stack error reports a missing component or property, before adding the declaration, check whether a plugin already provides it. The `expo-module-gradle-plugin` is opinionated about publishing setup; re-declaring its concerns produces silent or noisy duplicate errors. The minimal Expo Module build.gradle is shorter than the standard AGP library template.
