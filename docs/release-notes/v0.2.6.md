# v0.2.6 — relocate xcframeworks inside the podspec directory (B7)

iOS-only patch over v0.2.5. Release artifact bytes are byte-identical to v0.2.5; only the on-disk layout after postinstall changes, plus matching podspec path updates.

## What was broken (B7, surfaced on v0.2.5)

v0.2.5 fixed B6 (module bridging — added xcframework module map + Swift `import WalletCoreCommon`). With B2 ~ B6 cleared, xcodebuild reached SwiftCompile of `Sources/Generated/Account.swift` and failed immediately:

```
.../Sources/Generated/Account.swift:9:8: error: no such module 'WalletCoreCommon'
```

Hard evidence from the consumer pod target:

```
$ grep FRAMEWORK_SEARCH_PATHS Pods/Target\ Support\ Files/WalletCoreModule/WalletCoreModule.debug.xcconfig
FRAMEWORK_SEARCH_PATHS = $(inherited) "${PODS_ROOT}/React-Core-prebuilt" ... # no WalletCoreCommon entry

$ ls Pods/Target\ Support\ Files/WalletCoreModule/
WalletCoreModule-dummy.m  WalletCoreModule-prefix.pch  WalletCoreModule-umbrella.h
WalletCoreModule.debug.xcconfig  WalletCoreModule.modulemap  WalletCoreModule.release.xcconfig
# No WalletCoreModule-xcframeworks.sh — CocoaPods didn't process either xcframework.

$ find Pods -type d -name "WalletCoreCommon.xcframework"
# (empty)

$ grep WalletCoreCommon Pods/Pods.xcodeproj/project.pbxproj
# (empty)
```

CocoaPods silently dropped both `s.vendored_frameworks = ['../native/ios/WalletCoreCommon.xcframework', '../native/ios/WalletCoreRs.xcframework']` entries. The xcframeworks never made it into the build, so Swift never had a chance to see the `WalletCoreCommon` module — regardless of how good the injected module map was.

This is the same `..`-traversal asymmetry that bit `source_files` as B4 in v0.2.2. We'd assumed it was source_files-only; turns out `vendored_frameworks` has the exact same behaviour.

## Fix

`postinstall.js`: extract xcframeworks at `<pkg>/ios/` instead of `<pkg>/native/ios/`. The Swift sources were already there since v0.2.3. The Android AAR + proto.jar stay under `<pkg>/native/android/` because Gradle's `files(...)` accepts absolute paths and doesn't have the same glob-relative gotcha.

`ios/WalletCoreModule.podspec`: switch both `vendored_frameworks` entries to in-podspec-dir paths:

```ruby
# Before (v0.2.5)
s.vendored_frameworks = [
  '../native/ios/WalletCoreCommon.xcframework',
  '../native/ios/WalletCoreRs.xcframework',
]

# After (v0.2.6)
s.vendored_frameworks = [
  'WalletCoreCommon.xcframework',
  'WalletCoreRs.xcframework',
]
```

`source_files` was already in-podspec-dir since v0.2.3 — no change there.

## What changed in release artifacts

Bytes: zero change. The release tarball / xcframework zips are byte-identical to v0.2.5. Only postinstall lays them out at different paths on the consumer side.

| Asset | Path after postinstall (v0.2.5) | Path after postinstall (v0.2.6) |
|---|---|---|
| `WalletCoreCommon.xcframework` | `<pkg>/native/ios/` | **`<pkg>/ios/`** |
| `WalletCoreRs.xcframework` | `<pkg>/native/ios/` | **`<pkg>/ios/`** |
| `swift-sources.tar.gz` content | `<pkg>/ios/Sources/` | `<pkg>/ios/Sources/` (unchanged) |
| `wallet-core.aar` | `<pkg>/native/android/` | `<pkg>/native/android/` (unchanged) |
| `wallet-core-proto.jar` | `<pkg>/native/android/` | `<pkg>/native/android/` (unchanged) |

## Consumer migration

```bash
pnpm add @kyehyukahn/wallet-core@^0.2.6
pnpm install
pnpm exec expo prebuild --clean
# pod install now creates WalletCoreModule-xcframeworks.sh and adds the
# xcframeworks to FRAMEWORK_SEARCH_PATHS; xcodebuild can resolve
# `import WalletCoreCommon`.
```

No podspec / build.gradle changes needed on the consumer side.
