# v0.2.4 — Swift Protobuf import normalisation for CocoaPods

iOS-only patch over v0.2.3. xcframework / AAR / proto.jar binaries are byte-identical to v0.2.3; only the `swift-sources.tar.gz` content changes (60 `.pb.swift` files rewritten to use the canonical `import SwiftProtobuf` instead of upstream's SwiftPM-only `import WalletCoreSwiftProtobuf` alias).

## What was broken (B5, surfaced on v0.2.3)

v0.2.3 fixed B4 by relocating the swift sources to `<pkg>/ios/Sources/` so CocoaPods' `source_files` glob could match them without a `..` traversal. The relocation worked — consumer pod targets now ingest 222 swift files — but xcodebuild then failed immediately at SwiftCompile for every `.pb.swift`:

```
.../Sources/Generated/Protobuf/Ethereum.pb.swift:11:8: error: no such module 'WalletCoreSwiftProtobuf'
```

`tools/generate-files ios` runs a post-protoc sed pass that rewrites `import SwiftProtobuf` → `import WalletCoreSwiftProtobuf` (and `SwiftProtobuf.` → `WalletCoreSwiftProtobuf.`) so the upstream Trust Wallet Core SwiftPM target can re-export Apple's SwiftProtobuf under its own umbrella. CocoaPods consumers depend on the canonical `SwiftProtobuf` pod and have no such alias, so the rewritten imports don't resolve.

v0.2.0 through v0.2.3 all shipped the rewritten files; the failure only surfaced on v0.2.3 because earlier versions never reached SwiftCompile (the protobuf files were either missing — B3 — or excluded by the `..`-glob — B4).

## Fix

`tools/release-pack` now performs an inverse sed pass on `swift/Sources/Generated/Protobuf/**/*.swift` immediately before tar:

```
import WalletCoreSwiftProtobuf  →  import SwiftProtobuf
WalletCoreSwiftProtobuf.        →  SwiftProtobuf.
```

Paired with a post-tar invariant guard that extracts the tarball to a temp dir, greps for any surviving `WalletCoreSwiftProtobuf` reference, and exits non-zero if found. Combined with the existing v0.2.2 guards (`.pb.swift` count ≥ 1, `Ethereum/Solana/Common.pb.swift` presence), the release-pack now closes three classes of failure at pack time.

iOS-only patch — Android consumers can stay on v0.2.3 with no behaviour change. iOS consumers should bump to v0.2.4.

## Consumer migration

```bash
pnpm add @kyehyukahn/wallet-core@^0.2.4
pnpm install
pnpm exec expo prebuild --clean
```

`pod install` will pull the new sources via the existing podspec; no podspec changes required.
