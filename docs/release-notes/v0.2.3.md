# v0.2.3 — swift sources extract inside the podspec dir

Patch release. iOS-only fix. The TypeScript surface, native bridge
methods, error messages, proto shapes, and supported coin set are all
**identical to v0.2.0 / v0.2.1 / v0.2.2**.

## Why this release

Reported by the cirqle-mobile native dev. v0.2.2 fixed B3 — the
`.pb.swift` files are in the tarball — but the WalletCoreModule pod
still compiled only 3 swift files (`WalletCoreModule.swift` +
`chains/EvmSigning.swift` + `chains/SolanaSigning.swift`) and the
same `cannot find type 'TW_Ethereum_Proto_*'` errors fired at
`xcodebuild` time.

### Root cause

CocoaPods `source_files` is asymmetric with `vendored_frameworks`:

| Spec field | `..` parent-path glob | Result |
|---|---|---|
| `vendored_frameworks` | `'../native/ios/WalletCoreCommon.xcframework'` | OK — framework links cleanly |
| `source_files`        | `'../native/ios/Sources/**/*.swift'`            | silently matches **0** files |

`CocoaPods::Sandbox::PathList#absolute` (1.16) normalizes path
patterns relative to the podspec root and drops anything that escapes
it. There's no warning; the SwiftFileList just comes up short and
the consumer sees compile errors for missing symbols.

Hard evidence (post v0.2.2 install + `pod install`):

```
$ cat .../WalletCoreModule.SwiftFileList
.../@kyehyukahn/wallet-core/ios/WalletCoreModule.swift
.../@kyehyukahn/wallet-core/ios/chains/EvmSigning.swift
.../@kyehyukahn/wallet-core/ios/chains/SolanaSigning.swift
$ find .../node_modules/@kyehyukahn/wallet-core/native/ios/Sources -name '*.pb.swift' | wc -l
60          # files extracted correctly...
$ cat .../WalletCoreModule.SwiftFileList | wc -l
3           # ...but pod target ingests zero of them.
```

### Fix

Anchor the Swift tree inside the podspec directory by changing the
postinstall extraction destination, then drop the `..` from the
podspec glob. xcframeworks stay where they are — `vendored_frameworks`
handles `..` correctly, only `source_files` doesn't.

```
Before (v0.2.0–0.2.2)                After (v0.2.3+)

<pkg>/ios/                           <pkg>/ios/
├── WalletCoreModule.podspec         ├── WalletCoreModule.podspec
├── WalletCoreModule.swift           ├── WalletCoreModule.swift
└── chains/                          ├── chains/
                                     │   ├── EvmSigning.swift
                                     │   └── SolanaSigning.swift
                                     └── Sources/         ← NEW
                                         ├── Generated/
                                         │   └── Protobuf/
                                         │       ├── Ethereum.pb.swift
                                         │       └── Ethereum+Proto.swift
                                         └── ...
<pkg>/native/ios/                    <pkg>/native/ios/
├── Sources/  (extracted here)       ├── (only xcframeworks now)
├── WalletCoreCommon.xcframework     ├── WalletCoreCommon.xcframework
└── WalletCoreRs.xcframework         └── WalletCoreRs.xcframework
```

## What changed

| File | Change |
|---|---|
| `npm-package/postinstall.js` | ASSETS entry for `swift-sources.tar.gz` gains `root: 'pkg'` (vs default `'native'`); extraction destination is now `<pkg>/ios/Sources/` instead of `<pkg>/native/ios/Sources/`. Idempotency: the destination is wiped before extraction so a downgrade or partial-install state cannot leave stale `.swift` files. **New sanity guard:** after extraction, postinstall asserts `ios/Sources/Generated/Protobuf/Ethereum.pb.swift` is present, else exits 1 with a clear message. |
| `npm-package/ios/WalletCoreModule.podspec` | `source_files` `'../native/ios/Sources/**/*.swift'` → `'Sources/**/*.swift'`. `vendored_frameworks` unchanged (still `'../native/ios/...'`). |
| `npm-package/.gitignore` | adds `ios/Sources/` so a local postinstall run cannot accidentally bundle the extracted swift tree into the published npm tarball. |
| `npm-package/package.json` | `version` 0.2.2 → 0.2.3. |
| `tools/release-pack` | unchanged (the v0.2.2 `.pb.swift` count invariant still applies to the tarball). |
| Native xcframeworks (unzipped) / AAR / proto JAR / swift-sources content | **content unchanged from v0.2.2**. No native rebuild. The release-pack repacks the same underlying directories with `ditto`/`tar`, so the asset `.zip` / `.tar.gz` SHA-256s differ from v0.2.2 due to archive-metadata non-determinism (filesystem order, timestamps) — but the bytes a consumer sees after unzip/untar are identical. |

## Consumer migration: v0.2.2 → v0.2.3

```bash
pnpm add @kyehyukahn/wallet-core@^0.2.3
pnpm exec expo prebuild --clean
pnpm ios   # or pnpm android
```

Drop-in. No code change. No native bridge change. No TS API change.

The `<pkg>/native/ios/Sources/` directory will no longer be created
on fresh v0.2.3 installs. If you were grepping or symlinking that
path for development, point at `<pkg>/ios/Sources/` instead.

## Verification

- Local `npm install` runs postinstall successfully on v0.2.3 candidate.
- `find npm-package/ios/Sources -name "*.pb.swift" | wc -l` reports 60 after install.
- `Ethereum.pb.swift` is present with `public struct TW_Ethereum_Proto_Transaction`.
- Postinstall sanity guard fires on the negative case (verified by deleting `ios/Sources/` and rerunning).
- `pod ipc spec` parses the new podspec without warnings (no `..` patterns left).

Consumer-side: cirqle PR 3 Stage B `xcodebuild` rerun is the validating gate. Expect SwiftFileList to grow from 3 → 160+ entries; `TW_*_Proto_*` symbol resolution should resolve cleanly.
