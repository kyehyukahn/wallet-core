# v0.2.10 — Android build.gradle missing versionName

Android-only patch over v0.2.9. iOS xcframework / Swift sources / podspec are byte-identical to v0.2.9.

## What was broken (B8, surfaced on first consumer-side Android build)

After v0.2.9 closed iOS Stage B, the first consumer-side Android build via `./gradlew :app:assembleDebug` (or `pnpm exec expo run:android`) failed during the Expo autolinking configure phase:

```
A problem occurred configuring project ':kyehyukahn-wallet-core'.
> 'android.defaultConfig.versionName' is not defined
```

Our `npm-package/android/build.gradle` declared:

```gradle
android {
    namespace 'expo.modules.walletcore'
    compileSdk 35
    defaultConfig {
        minSdkVersion 23
        targetSdkVersion 35
    }
    ...
}
```

No `versionCode` / `versionName`. Standard Expo Modules pattern requires both — `expo-module-gradle-plugin` reads them at configure-time when it builds the autolinking metadata, and the modern AGP refuses to default them silently. v0.2.0~v0.2.9 all shipped this gap; it surfaced only on v0.2.10 because earlier iterations focused on iOS and the cirqle Android build had never been run end-to-end yet.

## Fix

```gradle
def package_version = '0.2.10'

group = 'expo.modules.walletcore'
version = package_version

android {
    namespace 'expo.modules.walletcore'
    compileSdk 35

    defaultConfig {
        minSdkVersion 23
        targetSdkVersion 35
        versionCode 1
        versionName package_version
    }
    ...
}
```

`versionCode` and `versionName` are now declared inside `defaultConfig` (where AGP expects them). The version string is hoisted into a Groovy variable at the top of the file so the npm bump can be mirrored with a one-line edit (avoids parsing package.json from Gradle — `groovy.json.JsonSlurper` works at runtime but the IDE diagnostic was noisy).
