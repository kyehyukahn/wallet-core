# v0.2.0 — self-contained Expo Module with chain-agnostic TS API

v0.2.0 turns `@kyehyukahn/wallet-core` from a binary bundle into a self-contained
React Native / Expo package. Consumers no longer write their own native
bridge — autolinking discovers the Expo Module shipped inside this package
and a chain-agnostic TypeScript API plus per-chain subpaths (EVM, Solana)
become available with a normal import.

## What changed since v0.1.0

### Added — package now ships

- **Expo Module bindings** (`ios/`, `android/` inside the npm tarball).
  Native Swift + Kotlin sources implementing `WalletCoreModule`. Discovered
  via `expo-module.config.json` at the package root, autolinked by Expo
  CLI's `prebuild`.
- **Chain-agnostic TypeScript core** at `@kyehyukahn/wallet-core`.
  - `CoinType` enum (Ethereum=60, Solana=501)
  - `HDWallet` class: `create`, `fromMnemonic`, `isValid`, `getMnemonic`,
    `deriveAddress(coin, path)`
- **EVM subpath** at `@kyehyukahn/wallet-core/evm`.
  - `signTransaction(tx, mnemonic, derivationPath?)` returns raw signed
    tx hex. Mode (Legacy / EIP-1559) inferred from gas field presence.
    EIP-2930 (type 1, access-list) intentionally unsupported.
  - `deriveAddress(mnemonic, derivationPath?)` returns EVM address.
  - `UnsignedEvmTx` type. uint256 fields as decimal strings (BigInt-safe);
    nonce and chainId as JS Number for ergonomics.
- **Solana subpath** at `@kyehyukahn/wallet-core/solana`.
  - `signTransfer(tx, mnemonic, derivationPath?)` for native SOL transfers.
  - `deriveAddress(mnemonic, derivationPath?)` returns base58 address.
  - `SolanaTransfer` type. lamports as decimal string (uint64).

### Changed

- `npm-package/package.json`: `main` → `dist/src/index.js`, with `exports`
  map for `./`, `./evm`, `./solana`, `./expo-module.config.json`.
  `typescript` added as a devDependency; CI now runs `npm ci && npm run
  build` before publish.
- `tools/release-pack`: also packages `swift-sources.tar.gz` and
  `wallet-core-proto.jar`. Both are hard preconditions.
- `release.yml`: builds `:wallet-core-proto:jar` after the AAR and runs
  `tsc -p tsconfig.json` inside `npm-package/` before publish.
- `postinstall.js`: ASSETS schema gains an explicit `extract` field
  (`unzip` | `untar` | `copy`). New `untarTo` helper.

### Removed

- `npm-package/index.js`, `npm-package/index.d.ts`. The path resolvers
  they exposed are no longer needed once autolinking takes over.

## Consumer migration: v0.1.x → v0.2.0

This is a **breaking change** for consumers that wrote their own Expo
Module / native bridge against v0.1.x's binary-only payload. The package
now provides the bridge; remove the duplicate.

For the cirqle-mobile reference consumer, the migration steps are:

1. `pnpm add @kyehyukahn/wallet-core@^0.2.0`.
2. `git rm -r apps/mobile/modules/wallet-core/` (the previous local
   Expo Module skeleton; replaced by the upstream package's module).
3. Add a thin TS provider that calls into the new subpath APIs and
   exposes whatever domain interface your app prefers. The cirqle
   pattern is `lib/wallet/providers/walletCore.ts` exposing an
   `EvmSigner` (see cirqle PR 3).
4. `pnpm exec expo prebuild --clean` to let autolinking discover the
   new Expo Module.
5. `pnpm ios` / `pnpm android` to validate.

## What you can import

```ts
// Chain-agnostic
import { HDWallet, CoinType } from '@kyehyukahn/wallet-core';

const wallet = await HDWallet.create();
const evmAddr = await wallet.deriveAddress(CoinType.Ethereum, "m/44'/60'/0'/0/0");
const solAddr = await wallet.deriveAddress(CoinType.Solana, "m/44'/501'/0'/0'");

// EVM
import { signTransaction, type UnsignedEvmTx } from '@kyehyukahn/wallet-core/evm';

const rawTx = await signTransaction(unsignedEvmTx, wallet.getMnemonic());

// Solana
import { signTransfer, type SolanaTransfer } from '@kyehyukahn/wallet-core/solana';

const encoded = await signTransfer(solTransfer, wallet.getMnemonic());
```

## Build & verification

Same toolchain as v0.1.0 (macOS, Xcode 16+, NDK 28.0.12674087, cmake 3.18.1,
Rust nightly-2025-12-11). `release.yml` adds two steps:

```
- ./gradlew :wallet-core-proto:jar      (inside android/)
- npm ci && npm run build               (inside npm-package/)
```

Both must succeed before `npm publish` runs. tsc strict mode enabled
(`strict: true`, `noUnusedLocals`, `noUnusedParameters`).
