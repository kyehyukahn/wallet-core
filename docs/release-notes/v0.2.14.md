# v0.2.14 — fix Kotlin EvmSigning / SolanaSigning AnySigner.sign generic call

Android-only patch over v0.2.13. iOS artifacts byte-identical. Symmetric to v0.2.9's iOS fix for the same bug class on the other platform.

## What was broken

After v0.2.13 cleared the Android configure issues (B8 / B9), gradle reached compileDebugKotlin and immediately failed:

```
.../android/src/main/java/expo/modules/walletcore/chains/EvmSigning.kt:62:37:
  e: Cannot infer type for this parameter. Specify it explicitly.
.../EvmSigning.kt:62:42:
  e: Argument type mismatch: actual type is 'ByteArray!', but 'MessageLite!' was expected.
.../EvmSigning.kt:62:73:
  e: No value passed for parameter 'p2'.
.../EvmSigning.kt:64:30:
  e: Unresolved reference 'encoded'.

(same shape in SolanaSigning.kt)
```

Our Kotlin code was calling:

```kotlin
val outputBytes = AnySigner.sign(builder.build().toByteArray(), CoinType.ETHEREUM)
val output = Ethereum.SigningOutput.parseFrom(outputBytes)
return "0x" + output.encoded.toByteArray().toHexString()
```

The actual `wallet.core.java.AnySigner.sign` signature is generic, mirroring the Swift one:

```java
public static <T extends MessageLite> T sign(MessageLite input, CoinType coin, Parser<T> parser) throws Exception
```

It takes the protobuf input object directly (not pre-serialised bytes), the CoinType, AND a Parser for the SigningOutput. It handles the byte round-trip internally and returns a typed SigningOutput.

The original scaffold guess of `sign(byte[], CoinType)` was a phantom signature that doesn't exist. When v0.2.9 fixed the symmetric bug on iOS (`AnySigner.sign(data:coin:)` → `AnySigner.sign<O>(input:coin:)`), I noted in the v0.2.9 release notes that "the Kotlin equivalent is correct — Java's AnySigner.sign takes raw bytes". That note was wrong; this patch corrects it.

## Fix

`EvmSigning.kt`:

```kotlin
// Before (v0.2.13 and earlier)
val outputBytes = AnySigner.sign(builder.build().toByteArray(), CoinType.ETHEREUM)
val output = Ethereum.SigningOutput.parseFrom(outputBytes)
return "0x" + output.encoded.toByteArray().toHexString()

// After (v0.2.14)
val output: Ethereum.SigningOutput = AnySigner.sign(
    builder.build(),
    CoinType.ETHEREUM,
    Ethereum.SigningOutput.parser(),
)
return "0x" + output.encoded.toByteArray().toHexString()
```

`SolanaSigning.kt` gets the same shape with `Solana.SigningOutput` instead.

## Lesson

Symmetric bugs on iOS and Android are the easy case for cross-platform code: when one side reveals an API mismatch, audit the other side BEFORE shipping the fix. I didn't on v0.2.9, hence the four-version detour through Android-specific build.gradle issues that happened to precede this Kotlin compile reveal.
