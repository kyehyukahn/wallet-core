## 3. Breez SDK 분석

### 3.1 Breez SDK란

Rust 기반 비트코인 Lightning SDK. 기존 Lightning 인프라 위에 개발자 친화적 API를 제공.
UniFFI로 Kotlin/Swift/RN/Flutter 바인딩 생성. 셀프 커스터디 방식.

### 3.2 세 가지 변종

| 변종 | 기반 | BOLT11 호환 | 특징 | 상태 |
|------|------|------------|------|------|
| **Greenlight** | CLN (Blockstream) | 네이티브 직접 | 사용자별 클라우드 노드, LSP 채널 관리 | deprecated 전환 중 |
| **Liquid** | Liquid Network | 서브마린 스왑 경유 | 채널 불필요, LBTC 기반, 페더레이션 신뢰 | 안정 |
| **Spark** | 노드리스 | 네이티브 직접 | 최신 아키텍처, 가장 간단한 통합 | 초기 단계 |

### 3.3 RN 패키지

- `@breeztech/react-native-breez-sdk` (Greenlight)
- `@breeztech/react-native-breez-sdk-liquid` (Liquid)
- `@breeztech/breez-sdk-spark-react-native` (Spark)
- Breez API Key 필요 (support@breez.technology)

### 3.4 GitHub 저장소

## 5. 통합 방식 후보

### A) wallet-core 코어에 직접 통합

- Lightning 구현체(LDK 등)를 C++/Rust 코어에 임베드
- 장점: 통일된 API (`TWAnySigner`), 모든 wallet-core 사용자 혜택
- 단점: **작업량 극히 높음**, wallet-core 설계 철학(오프라인 서명)과 충돌, Lightning은 상시 네트워크 프로토콜

### B) RN 앱 레벨에서 별도 통합

```
RN App
├── wallet-core (온체인: BTC, ETH, SOL...)
└── Breez SDK (Lightning: 송금, 수금, 채널)
```

- 장점: **가장 빠른 통합** (npm install), wallet-core 수정 불필요, Breez 업데이트 바로 반영
- 단점: 키 관리 이원화 (니모닉 2개), 앱 바이너리 크기 증가

### C) 하이브리드 (추천 후보)

```
RN App
├── wallet-core → 니모닉/키 생성, 온체인 서명
└── Breez SDK → wallet-core 키로 Lightning 노드 초기화
```

- 장점: **하나의 니모닉**으로 온체인 + Lightning 통합, 사용자 백업 1개
- 단점: Breez SDK 외부 키 주입 지원 여부 확인 필요, 키 파생 경로 호환성 검증 필요

### 비교 요약

| 기준 | A (코어) | B (앱 레벨) | C (하이브리드) |
|------|---------|-----------|-------------|
| 개발 난이도 | 극히 높음 | 낮음 | 중간 |
| 통합 속도 | 수개월 | 수일~수주 | 수주 |
| 사용자 경험 | 최고 | 보통 | 좋음 |
| 유지보수 | 극히 높음 | 낮음 | 중간 |

## 6. 호환성 참고

- 모든 Lightning 월렛은 **BOLT11 인보이스** 표준 사용 → Breez SDK 3종 모두 호환
- Greenlight/Spark는 네이티브 Lightning → 직접 호환
- Liquid는 서브마린 스왑 경유 → 호환되지만 추가 지연/수수료
- LNURL 프로토콜도 3종 모두 지원
