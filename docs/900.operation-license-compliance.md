## 2. 발견된 문제점

### 2-1. breadwallet-core 포팅 코드의 저작권 고지 누락 (중요도: 높음)

**현황:**

`tw_spv` crate의 아래 파일들이 breadwallet-core의 알고리즘을 Rust로 포팅하면서, 코멘트로 출처를 언급하고 있으나 MIT 라이센스가 요구하는 **저작권 고지(copyright notice)와 허가 고지(permission notice)** 를 포함하고 있지 않다.

- `rust/frameworks/tw_spv/src/merkle_block.rs` (line 71, 157) — `BRMerkleBlockTxHashes()` 알고리즘 포팅
- `rust/frameworks/tw_spv/src/bloom_filter.rs` (line 8) — `BRBloomFilter.c` 동작 매칭

**문제:**

MIT 라이센스의 유일한 의무 조건은 다음과 같다:

> "The above copyright notice and this permission notice shall be included in all copies or **substantial portions** of the Software."

알고리즘의 핵심 로직을 포팅한 경우 "substantial portions"에 해당할 수 있으며, 현재 SPDX 헤더는 `Apache-2.0 / Copyright © 2017 Trust Wallet`만 기재되어 있다. breadwallet LLC의 저작권 고지가 없다.

**필요 조치:**

1. 포팅된 파일의 헤더에 breadwallet-core 저작권 고지 추가
2. `LICENSE-3RD-PARTY.txt`에 breadwallet-core MIT 라이센스 전문 추가

### 2-2. Rust crate manifest에 license 필드 미기재 (중요도: 중간)

**현황:**

`tw_spv`를 포함한 모든 Rust crate(`tw_hash`, `tw_encoding`, `tw_memory`, `tw_utxo`)의 `Cargo.toml`에 `license` 필드가 없다.

**문제:**

- `cargo publish` 시 라이센스 정보 없이는 게시 불가 (현재 publish하지 않으므로 당장 차단되지는 않음)
- 하지만 의존성 감사 도구(`cargo-deny`, `cargo-license`)가 라이센스를 인식하지 못함
- 프로젝트 루트의 `LICENSE` 파일이 Apache-2.0이므로 각 crate가 이를 명시적으로 선언해야 일관성이 보장됨

**필요 조치:**

`tw_spv/Cargo.toml` 및 기타 Rust crate에 아래 필드 추가:

```toml
[package]
license = "Apache-2.0"
```

### 2-3. byteorder 의존성 라이센스 호환성 (중요도: 낮음)

**현황:**

`byteorder` crate는 **MIT OR Unlicense** 듀얼 라이센스다.

**결론:**

MIT와 Unlicense 모두 Apache-2.0과 완전 호환된다. 추가 조치 불필요. 단, `LICENSE-3RD-PARTY.txt` 갱신 시 목록에 포함하는 것을 권장한다.

### 2-4. LGPL-2.1 (check 라이브러리) 프로덕션 포함 여부 (중요도: 조건부)

**현황:**

`check` 라이브러리(C 테스트 프레임워크)가 `build/local/src/check/`에 존재하며 LGPL-2.1이다.

**결론:**

테스트 빌드에만 사용되고 프로덕션 바이너리(iOS/Android SDK)에 포함되지 않는다면 LGPL 의무가 발생하지 않는다. **릴리스 빌드에서 check가 링크되지 않는지 확인만 하면 된다.**

### 작업 D: 릴리스 빌드에서 LGPL 컴포넌트 제외 확인 (권장)

`check` 라이브러리(LGPL-2.1)가 iOS/Android/WASM 릴리스 빌드에 링크되지 않는지 확인한다.

확인 방법 예시:

```bash
# iOS 프레임워크에서 check 심볼 검색
nm -g <framework_binary> | grep -i "ck_assert\|check_"

# Android SO에서 check 심볼 검색
nm -D <libTrustWalletCore.so> | grep -i "ck_assert\|check_"
```

결과가 없으면 문제없음.

## 4. Phase 2 (tw_wallet_manager) 추가 고려사항

Phase 2에서 `tw_wallet_manager` crate를 생성할 때도 동일한 패턴이 적용된다:

1. breadwallet-core의 wallet state 관리 로직(`BRWallet.c` 등)을 포팅하는 경우 **작업 A와 동일한 저작권 고지**를 해당 파일에 추가해야 한다
2. 신규 외부 의존성이 추가되면 라이센스 호환성을 확인하고 `LICENSE-3RD-PARTY.txt`를 갱신해야 한다
3. `Cargo.toml`에 `license = "Apache-2.0"` 필드를 포함해야 한다

## 5. 라이센스 호환성 매트릭스

아래는 현재 프로젝트에서 사용되는 모든 라이센스와 Apache-2.0 기본 라이센스 간의 호환성이다.

| 서드파티 라이센스 | Apache-2.0과 호환 | 조건 |
|------------------|-------------------|------|
| MIT | 호환 | 저작권/허가 고지 유지 |
| BSD-3-Clause | 호환 | 저작권 고지 유지, 이름 보증 금지 |
| BSL-1.0 (Boost) | 호환 | 저작권 고지 유지 |
| Unlicense | 호환 | 조건 없음 |
| LGPL-2.1 | **조건부 호환** | 동적 링크 시 호환, 정적 링크 시 리링크 수단 제공 필요 |
| Apache-2.0 (Protobuf) | 동일 라이센스 | 완전 호환 |
