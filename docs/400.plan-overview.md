# 400. Bitcoin Feature Improvement — Implementation Plan Overview

> Phase 1~4 구현 계획의 총괄 문서. 각 Phase의 상세 계획은 개별 문서 참조.

**Design Spec:** [300.design_bitcoin_improvemet.md](300.design_bitcoin_improvemet.md)
**Branch:** `features/bitcoin_spv`
**Status:** Phase 1~4 구현 완료, 앱 통합(FFI) 미완

---

## 1. 프로젝트 목표

breadwallet-core의 검증된 Bitcoin SPV 구현을 wallet-core의 Rust 레이어로 이식하여:

1. 중앙 서버 없이 Bitcoin 네트워크에 직접 연결 (SPV/P2P)
2. UTXO 추적, 잔액 관리, 주소 파생 등 월렛 상태 관리
3. 수수료 계산 고도화, BIP38 키 암호화
4. Bitcoin Cash, Litecoin, Dogecoin 확장

기존 `CoinEntry`/`TWAnySigner` 서명 API는 변경하지 않으며, SPV/Wallet은 선택적 상위 레이어로 추가한다.

## 5. 아키텍처 통합

### 기존 서명 API와의 관계

```
기존 (유지, 변경 없음):
  앱 → TWAnySigner → CoinEntry::sign() → 트랜잭션 서명 (stateless)

신규 (선택적 추가):
  앱 → TWHDWallet (C++) → xpub 생성
                              ↓
       BitcoinWalletManager (Rust)
            ├── Wallet → 주소/UTXO/TX 관리
            ├── SyncManager → PeerManager → P2P 동기화
            └── Persistence → 앱이 저장 구현체 제공
```

SPV를 사용하지 않는 앱은 기존 `TWAnySigner`만으로 계속 동작한다.

### 니모닉/HD Wallet

니모닉 생성과 HD 키 파생은 기존 C/C++ 구현(`TWHDWallet`, `trezor-crypto/bip39.c`)을 그대로 사용한다. 우리 Rust 구현은 생성된 xpub을 받아서 동작한다.

```
TWHDWalletCreate() → 니모닉 → seed → master key → xpub
                                                     ↓
                                      AddressManager (Rust) → 주소 파생
```

## 6. 앱 통합 (미완 — 향후 작업)

현재 `tw_spv`와 `tw_wallet_manager`는 Rust crate로만 존재한다. 앱(iOS/Android/WASM)에서 사용하려면 FFI 연결 코드를 추가 작성해야 한다:

| 단계 | 작업 | 파일 |
|------|------|------|
| 1 | Rust FFI 함수 작성 | `wallet_core_rs/src/ffi/tw_wallet_manager.rs` (신규) |
| 2 | C 헤더 작성 | `include/TrustWalletCore/TWWalletManager.h` (신규) |
| 3 | Cargo 의존성 추가 | `wallet_core_rs/Cargo.toml` |
| 4 | 바인딩 재생성 | `tools/generate-files` (Swift/Kotlin/WASM 자동 생성) |

이것은 빌드 설정이 아닌 **코드 작성 작업**이다.

## 9. 설계 변경 이력

| 변경 | 이유 | 설계 문서 참조 |
|------|------|---------------|
| `pthread` → `async`/`SpvRuntime` trait | 모바일 리소스 절약, runtime 비노출 | §7 |
| C 콜백 → typed enum events | 타입 안전성 | §12 |
| `BRSet` → `HashMap` | Rust 표준 라이브러리 | §3 |
| `BTreeSet<Utxo>` → `HashMap<OutPoint, UtxoRecord>` | coin selection 정책 분리 | §10 |
| BIP37 only → `SyncCapability` fallback | BIP37 가용성 제한 대응 | §9 |
| `SpvContext` 단일 trait → `SpvChain` + `WalletChain` 분리 | 타입 경계 명확화 | §6-4 |
| Persistence 범위 확장 | crash recovery에 필요한 상태 누락 방지 | §11 |
| `save_headers_batch` / `save_sync_progress` 추가 | 원자적 저장으로 불일치 방지 | §11-2b |
| `FilterStrategy` trait 예약 | BIP157/158 마이그레이션 경로 | §9-5 |
| Phase 1 범위를 Bitcoin only로 축소 | 현실적 deliverable 확보 | §2 |
