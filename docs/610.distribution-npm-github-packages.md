# 610. 배포 절차 — GitHub Releases + npm wrapper (GitHub Packages)

이 포크의 네이티브 산출물(iOS xcframeworks + Android AAR)을 외부 소비자
(주: cirqle-mobile)에게 배포하는 표준 절차.

## 0. 구조

```
GitHub Releases (kyehyukahn/wallet-core)
  └─ v<X.Y.Z>/
      ├─ WalletCoreCommon.xcframework.zip
      ├─ WalletCoreRs.xcframework.zip
      ├─ wallet-core.aar
      └─ SHA256SUMS

GitHub Packages npm registry (npm.pkg.github.com)
  └─ @kyehyukahn/wallet-core@X.Y.Z
      └─ 얇은 wrapper (postinstall이 위 Release에서 다운+검증+풀기)
```

- 산출물 바이너리는 **Releases**가 호스팅 (~390 MB / 버전).
- npm 패키지는 KB 단위의 wrapper만 담는다 (postinstall.js + index.js + 메타).
- 소스 리포 `kyehyukahn/wallet-core`가 PUBLIC이므로 publish되는 패키지도 자동 PUBLIC.

## 1. 사전 준비 (1회)

### 1.1 발행자 측 인증

```bash
# ~/.npmrc 에 GitHub Packages 토큰 등록
TOKEN=$(gh auth token)        # write:packages 스코프 포함 권장
echo "//npm.pkg.github.com/:_authToken=${TOKEN}" >> ~/.npmrc
```

`gh auth login` 시 토큰 스코프에 `write:packages`가 포함돼 있어야 한다.
부족하면 `gh auth refresh -s write:packages`.

### 1.2 빌드 환경

[docs/600.build-prerequisites.md](600.build-prerequisites.md) 참고. 첫
빌드 시 30분 정도 소요.

## 2. 새 버전 절차 (반복)

### Step 1: 산출물 빌드

```bash
tools/install-rust-dependencies           # 최초 또는 nightly 갱신 시
tools/install-android-dependencies        # NDK + cmake;3.18.1
tools/generate-files ios
tools/ios-build
tools/generate-files android
tools/android-build
```

각각이 성공하면 다음 파일이 만들어진다:

- `build/ios-frameworks/WalletCoreCommon.xcframework`
- `swift/WalletCoreRs.xcframework`
- `build/wallet-core.aar`

### Step 2: 산출물 패키징

```bash
tools/release-pack <version>             # 예: tools/release-pack 0.1.1
```

결과: `build/release-v<version>/` (4개 파일 — zip 2 + aar + SHA256SUMS).
이 디렉터리는 `.gitignore` 처리되어 있다.

### Step 3: 패키지 버전 동기화 + 커밋 + 태그

```bash
# npm-package/package.json 의 "version" 필드를 동일 버전으로 수정
$EDITOR npm-package/package.json
git add npm-package/package.json
git commit -m "chore(npm): bump @kyehyukahn/wallet-core to <version>"

git tag -a v<version> -m "v<version>"
git push origin <branch>
git push origin v<version>
```

### Step 4: GitHub Release 생성

```bash
gh release create v<version> \
    --target dev \
    --title "v<version>" \
    --notes-file docs/release-notes/v<version>.md \
    build/release-v<version>/*
```

`docs/release-notes/v<version>.md`는 미리 작성. v0.1.0 노트를 템플릿으로 사용.

### Step 5: npm 패키지 publish

```bash
cd npm-package
npm publish
# → https://github.com/kyehyukahn/wallet-core/packages 에서 확인
```

publish는 `package.json`의 version과 같은 태그(`v<version>`)가
Release로 존재해야 의미가 있다 (postinstall이 그 URL에서 다운로드).

## 3. 소비자 측 셋업 (참고)

**GitHub Packages npm은 패키지 가시성과 무관하게 install 시 항상 인증 토큰을
요구한다** (npmjs.org와의 결정적 차이). 따라서 소비자 프로젝트 `.npmrc`에는
스코프 매핑 + 인증 토큰 **두 줄 모두** 필요하다:

```
# 소비자 프로젝트 루트 .npmrc
@kyehyukahn:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

`${GITHUB_TOKEN}`은 `read:packages` 스코프만 있으면 충분하다. 개인 개발자는
`gh auth token`(또는 GitHub Personal Access Token)을 셸 환경 변수로 export
하거나 `.npmrc`에 평문으로 넣는다. CI는 `secrets.GITHUB_TOKEN`을 그대로 사용.

> 참고: `.npmrc`에 평문 토큰을 넣을 경우 그 파일을 절대 commit하지 말 것
> (root `.gitignore`에 `.npmrc` 또는 `.npmrc.local` 등록 권장).

설치:

```bash
pnpm add @kyehyukahn/wallet-core@^0.1.0
```

postinstall이 `https://github.com/kyehyukahn/wallet-core/releases/download/v<version>/`
에서 산출물을 받아 `node_modules/@kyehyukahn/wallet-core/native/` 아래에
배치한다. SHA256SUMS를 받아 각 파일 무결성을 검증한다.

Release 자산 자체(`.zip` / `.aar` / `SHA256SUMS`)는 PUBLIC 리포의 Release이므로
**익명으로 다운로드 가능** (postinstall도 토큰 없이 가져옴). 인증은 npm 레지스트리에서
패키지 메타데이터를 조회·tarball을 받을 때만 필요하다.

## 4. 자주 묻는 것

**Q. 패키지를 public으로 바꿔도 토큰이 필요한 이유?**
A. GitHub Packages npm 레지스트리는 가시성과 무관하게 항상 인증을 요구한다
(2026년 기준). npmjs.org만 익명 install이 가능. 이 제약을 피하려면 npmjs.org로
이전 publish하거나, fetch 스크립트 방식으로 우회.

**Q. 첫 publish 후 패키지가 private으로 만들어지는 이유?**
A. GitHub Packages 개인 계정 npm 패키지의 초기 가시성은 `private`이 기본이다
(repo 가시성과 자동 동기화되지 않는다). 첫 publish 후
`https://github.com/users/<owner>/packages/npm/package/<name>` →
Package settings → Danger zone → Change visibility에서 수동으로 public 전환.

**Q. 빌드 산출물을 git에 직접 넣지 않는 이유?**
A. xcframework / AAR 슬라이스가 GitHub의 파일당 100 MB 제한을 초과하고,
LFS는 1 GB 무료 quota를 빠르게 소진한다. Releases는 산출물 호스팅에
최적화되어 있고 별도 비용 없이 대용량을 다룬다.
[docs/603.build-ios.md](603.build-ios.md) / [604.build-android.md](604.build-android.md)
의 산출물 크기 절 참고.

**Q. cirqle 이외의 소비자가 늘면?**
A. 동일 메커니즘으로 동일 패키지에 의존하면 된다. 향후 정책상
조직 자산화가 필요해지면 리포를 적절한 GitHub 조직으로 transfer.

## 5. 자동화 후보 (향후 작업)

- `.github/workflows/release.yml`: `v*` 태그 push 시 macOS runner에서
  iOS+Android 빌드 → release-pack → gh release create → npm publish.
- 첫 빌드(~30분) 캐시를 위해 `cargo-cache`, `bootstrap`의 `build/local`을
  GitHub Actions cache로 저장.
- 현재는 수동. 1~2회 더 수동 발행한 뒤 패턴이 굳으면 자동화.
