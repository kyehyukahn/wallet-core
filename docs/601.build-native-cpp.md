# 601. C++ 네이티브 빌드 (macOS / Linux)

wallet-core의 핵심인 C++ 코어 라이브러리를 빌드하고 테스트하는 방법.

## 사전 조건

- [600. 빌드 사전 준비](600-build-prerequisites.md) 완료
- 또는 `./bootstrap.sh` 실행 완료

## 빌드 흐름 개요

```
bootstrap.sh (최초 1회)
    ↓
tools/generate-files native    ← .proto, registry.json 변경 시 필수
    ↓
cmake configure               ← 빌드 시스템 생성
    ↓
make                          ← 컴파일
    ↓
tests 실행                    ← 검증
```

## Step 1: 코드 생성 (generate-files)

`.proto` 파일이나 `registry.json`을 수정했다면 반드시 실행:

```bash
tools/generate-files native
```

이 스크립트가 수행하는 작업:
1. `codegen/bin/coins` — registry.json에서 코인 정보 생성
2. `tools/rust-bindgen native` — Rust 라이브러리 빌드 + C 바인딩 헤더 생성
3. `codegen/bin/codegen` — C++/Java 인터페이스 코드 생성
4. `protoc` — .proto 파일에서 C++/Java protobuf 코드 생성
5. protoc 커스텀 플러그인 — C typedef, Swift typealias 생성

> **핵심**: `tools/rust-bindgen native` 내부에서 `cargo build --release --lib`이 실행된다.
> Rust 코어 (`libwallet_core_rs.a`)가 빌드되어 `build/local/lib/`에 복사된다.

## Step 2: CMake 설정

```bash
cmake -H. -Bbuild -DCMAKE_BUILD_TYPE=Debug \
    -DCMAKE_C_COMPILER=clang \
    -DCMAKE_CXX_COMPILER=clang++
```

### CMake 옵션

| 옵션 | 기본값 | 설명 |
|------|--------|------|
| `CMAKE_BUILD_TYPE` | - | `Debug` 또는 `Release` |
| `TW_UNIT_TESTS` | ON | 테스트 타겟 포함 |
| `TW_BUILD_EXAMPLES` | OFF | walletconsole 빌드 |
| `TW_UNITY_BUILD` | OFF | Unity build (빌드 속도 향상) |
| `TW_CODE_COVERAGE` | OFF | 코드 커버리지 계측 |
| `TW_CLANG_ASAN` | OFF | AddressSanitizer |
| `TW_ENABLE_CLANG_TIDY` | OFF | clang-tidy 정적 분석 |
| `TW_ENABLE_PVS_STUDIO` | OFF | PVS-Studio 정적 분석 |

### 빌드 결과물 (standalone 모드)

```
build/
├── libTrustWalletCore.a      ← 정적 라이브러리
├── tests/
│   └── tests                 ← C++ 단위 테스트 바이너리
└── trezor-crypto/
    └── crypto/tests/
        └── TrezorCryptoTests ← 저수준 암호 테스트 바이너리
```

## Step 3: 컴파일

```bash
# 라이브러리 + 테스트 전부 빌드
make -Cbuild -j12 tests TrezorCryptoTests

# 라이브러리만 빌드 (테스트 제외)
make -Cbuild -j12 TrustWalletCore
```

> `-j12`는 병렬 빌드 스레드 수. CPU 코어 수에 맞게 조정.

## Step 4: 테스트 실행

```bash
# C++ 전체 단위 테스트
./build/tests/tests

# 특정 블록체인 테스트만
./build/tests/tests --gtest_filter="*Bitcoin*"
./build/tests/tests --gtest_filter="*Ethereum*SignTest*"

# TrezorCrypto 저수준 암호 테스트
export CK_TIMEOUT_MULTIPLIER=4
./build/trezor-crypto/crypto/tests/TrezorCryptoTests
```

### 자주 쓰는 gtest 필터 패턴

```bash
# 특정 체인의 서명 테스트
./build/tests/tests --gtest_filter="*Solana*Sign*"

# 특정 체인의 주소 테스트
./build/tests/tests --gtest_filter="*Cosmos*Address*"

# 여러 패턴 조합 (: 로 구분)
./build/tests/tests --gtest_filter="*Bitcoin*:*Ethereum*"

# 특정 패턴 제외 (- 접두사)
./build/tests/tests --gtest_filter="*Bitcoin*:-*Slow*"
```

## 원스텝 빌드 + 테스트

`tools/build-and-test`는 위의 모든 과정을 한 번에 수행:

```bash
tools/build-and-test              # 전체 테스트
tools/build-and-test Bitcoin      # Bitcoin 관련 테스트만
```

실행 순서:
1. `tools/generate-files native`
2. `cmake` 설정
3. `make -j12 tests TrezorCryptoTests`
4. `tools/lint` (clang-tidy가 있으면)
5. TrezorCryptoTests 실행
6. C++ 단위 테스트 실행

## Lint

```bash
# 변경된 파일만 lint (master 대비 diff)
tools/lint

# 전체 lint
tools/lint-all
```

## 빌드 시간 참고

| 단계 | 대략적 시간 (M1 Mac, 첫 빌드) |
|------|------|
| bootstrap.sh (전체) | 15~30분 |
| Rust 라이브러리 (cargo build --release) | 5~10분 |
| C++ cmake + make | 5~10분 |
| 테스트 실행 | 1~3분 |

> 이후 증분 빌드는 변경 범위에 따라 수초~수분.
